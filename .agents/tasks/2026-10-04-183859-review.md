## Stock tracking system and rollback completeness

The stock system (lines 350-367) provides getSoldCount, incrementSold, and decrementSold operating on shop-sold.json. The file is initialized on module load at line 349.

The purchase handler (lines 516-622) implements the deduct-first pattern:

1. Defer reply before busyUsers.add (line 519) — this addresses the prior review's edge-case concern about defer throwing and leaving busyUsers dirty.
2. Filter skipped items (lines 534-549) — removes already-owned roles and out-of-stock items.
3. Check balance (lines 551-563).
4. Deduct currencies and increment sold counts (lines 566-583) — snapshot old balance, subtract from currencies.json, save immediately, call incrementSold for each item with stock.
5. Assign roles and add to inventory (lines 585-594) — loop through targets, create or find roles, assign to member, call addToInventory.
6. On catch (lines 595-617) — log error, rollback currencies by restoring old balance, call decrementSold to restore stock, **rollback inventory** by decrementing counts and deleting zero entries (lines 599-608), notify user of rollback.

The rollback path at lines 599-608 is new since the prior review. It iterates through targets, loads inventory, decrements the item count for each target, removes entries that reach zero, and saves. This closes the gap identified in the prior pass where users retained phantom inventory entries on role-assignment failure.

## busyUsers cleanup and defer ordering

The busyUsers Set is declared at module level (line 369). The purchase handler adds userId at line 527, inside the try block of a try/finally that runs busyUsers.delete(userId) at line 620.

The deferReply call at line 519 is **before** busyUsers.add. If deferReply throws (interaction already deferred by a race or hook), the code returns early and never marks the user busy. This addresses the prior review's concern that a defer exception could leave busyUsers dirty.

## buildShop structure and parseEmoji
