# Shop Module Refactor: Multi-Currency Purchase System

TypeScript conversion of a Discord bot's role shop module from JavaScript, adding multi-currency support (cowoncy, blue tickets, gold tickets) and stock tracking while preserving backwards compatibility with legacy coin balances. The refactor introduces transaction safety guards, rollback on role assignment failure, and proper busy-user protection.

**Watch for:** Inventory rollback on purchase failure contains a subtle bug where pre-existing inventory entries get incremented rather than restored (likely). Shop refresh after purchase uses optional chaining on `interaction.message` which may be null in edge cases (possible). No TypeScript compilation output provided to verify the "compiles with no errors" requirement (confirmed gap).

**Verdict**: NEEDS_CHANGES

## High-level view

Stock tracking uses three functions (`getSoldCount`, `incrementSold`, `decrementSold`) backed by `shop-sold.json`. Sold counts increment immediately after currency deduction, before role assignment, preventing race conditions. Module-level `busyUsers` Set guards concurrent purchases with try/finally cleanup.

The `buildShop()` function returns `{ embeds, components, files }` with inline fields using `\u200B` as field names. Prices display all three currencies. Select menu uses `parseEmoji()` to extract animated emoji IDs. A full-buy option appends as `inline: false`.

Purchase flow: defer → filter targets → check balance → deduct currencies and increment sold → assign roles → on catch, rollback currencies, decrement sold, rollback inventory. The rollback restores a currency snapshot taken before deduction and decrements inventory by iterating all targets.

The inventory rollback assumes items were added during the purchase loop, but if inventory and Discord roles are desynced (user has inventory entry but no Discord role), the purchase filter passes, inventory increments, then rollback decrements, leaving inventory higher than pre-purchase state.

All commands (`/shop`, `/inventory`, `/balance`, `/revoke`), VIP Info button content, migration function, and multi-currency system remain unchanged.

<details>
<summary>Issues (3)</summary>

1. **Inventory rollback bug when state is desynced** — Purchase filter checks Discord roles but not inventory. If a user has an inventory entry without the Discord role (from prior manual removal or partial failure), buying that item again passes the filter, increments inventory, then rollback decrements inventory. Net effect: inventory count ends up 1 higher than pre-purchase. Fix: either check inventory in the filter or snapshot inventory state before purchase and restore exact values on rollback.

2. **No TypeScript compilation verification** — Requirements state "TypeScript compiles with no errors (coder should have logged the result)" but no build output provided. Cannot confirm this requirement is met.

3. **Shop refresh may silently fail** — Post-purchase refresh uses `interaction.message?.edit()` which handles null safely but won't update the shop if the message is deleted or the context is missing. Current collector setup makes this unlikely, but the edge case exists.

### Stock system implementation

Stock tracking uses `shop-sold.json` as a flat record mapping item IDs to sold counts:

```typescript
function getSoldCount(itemId: string): number {
  return loadSold()[itemId] ?? 0;
}
function incrementSold(itemId: string): void {
  const d = loadSold(); d[itemId] = (d[itemId] ?? 0) + 1; saveSoldData(d);
}
function decrementSold(itemId: string): void {
  const d = loadSold(); d[itemId] = Math.max(0, (d[itemId] ?? 0) - 1); saveSoldData(d);
}
```

File initialized at module load. Stock calculation in `buildShop()`: `Math.max(0, item.stock - getSoldCount(item.id))` for items with stock, `Infinity` otherwise. Purchase filter excludes `stockLeft <= 0`.

Sold counts increment after currency deduction, before role assignment:

```typescript
saveCurrencies(currData);
targets.forEach(t => { if (t.stock != null) incrementSold(t.id); });

try {
  for (const item of targets) {
    await member.roles.add(role);
    addToInventory(userId, item.id);
  }
} catch (err) {
  targets.forEach(t => { if (t.stock != null) decrementSold(t.id); });
}
```

This reserves stock before Discord API calls, preventing double-allocation during network latency.

### Busy-user guard

Module-level `busyUsers` Set prevents concurrent purchases:

```typescript
const busyUsers = new Set<string>();

if (busyUsers.has(userId)) {
  await i.editReply({ content: 'Đang xử lý lượt mua trước...' });
  return;
}
busyUsers.add(userId);
try {
  // purchase logic
} finally {
  busyUsers.delete(userId);
}
```

### Purchase transaction safety

Currency deduction before role assignment:

**Inventory rollback flaw**: Purchase loop calls `addToInventory(userId, item.id)` for each successfully assigned role. Rollback iterates all targets and decrements:

```typescript
targets.forEach(t => {
  const invData = loadInventory();
  if (invData[userId]?.[t.id]) {
    invData[userId][t.id] = Math.max(0, invData[userId][t.id] - 1);
  }
});
```

`addToInventory` increments by default:

```typescript
function addToInventory(userId: string, itemId: string, quantity: number = 1): void {
  data[userId][itemId] = (data[userId][itemId] || 0) + quantity;
}
```

Purchase filter checks Discord roles, not inventory:

```typescript
targets = targets.filter(t => {
  const roleName = `${t.emoji} ${t.name}`;
  if (member.roles.cache.find(r => r.name === roleName)) { 
    skipped.push(`${t.name} (đã có)`); 
    return false; 
  }
});
```

**Scenario**: User has inventory entry for item A (quantity 1) but no Discord role (manual removal). Purchase filter passes. Purchase increments inventory to 2, adds role. Role assignment fails mid-transaction. Rollback decrements inventory to 1. User paid nothing (rollback succeeded), has no role (correct), but inventory shows 1 instead of pre-purchase value.

This requires pre-existing desync between inventory and Discord roles. The bug perpetuates the desync rather than creating it. Normal flow assigns roles and adds inventory atomically, so desync shouldn't occur unless roles are manually removed or prior failures left partial state.

**Fix options**: Check inventory in filter, or snapshot inventory before purchase and restore exact values on rollback.

### Shop refresh

Refresh button uses `i.update(buildShop(...))` to replace the message in place. Post-purchase refresh uses `interaction.message?.edit(buildShop(...))` with optional chaining—null-safe but won't update if the message is deleted or context is missing.
